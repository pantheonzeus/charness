# Regression cases — `audience-of-one-report`

Concrete failures the skill has shipped, as input → trap → expected-behaviour → mechanical hook. Use as eval anchors: a change that lets any of these regress is a regression, no matter what else it improves.

## RC-1 — Filtered-dataset zero read as a capability gap (fictionalized composite, v7.3)
**Context.** Reference entity = a fictional industrial manufacturer ("Meridian Power Systems," the buyer). Structured input gave Meridian's filtered data/AI cluster as **38 roles, senior_ic_pct 0, sig_mlops_pct 0**.
**Trap.** The brief read `0/38` as a *capability* statement ("thinnest production-AI core", "missing its senior layer") and made it an exec headline stat + the centerpiece chart, with Meridian a near-zero bar beside peers and an absent named peer. Mis-framed twice more (hollow-core → "built but hidden" → "built and visible"), each revision written off whichever source was most recent.
**Ground truth.** An independent same-pipeline live job-board census (180 postings) found senior data/AI, software, FPGA, cyber roles at ~14% — so `0` was a sampling artifact of a filtered source on a small base, not a gap.
**Expected under v7.4.** Proxy reading (item 1) — a `0`/low/absent on a small base, for the reference entity, on a negative claim gets maximal skepticism. second_source (item 2 / §10-A) — `0/38` can't anchor spine/headline/centerpiece without a comparable-basis second source; with none it ships only as a flagged directional note. One axis one basis (item 3 / §10-B) — Meridian (filtered n=38) can't sit as a comparable bar beside peers + an absent named peer (fix: two-panel `c2`). Alternative needs data (item 4) — "keep the filtered chart + a caveat" is not offered as equivalent. Imported findings are leads (item 6). Critic probe (§10-D) blocks it. **Pass criterion:** a v7.4 run either doesn't surface `0/38` as a headline/centerpiece, or does so only after a comparable second source corroborates, with any cross-entity chart single-basis or panel-separated.

## RC-2 — Two soft sources read as corroboration on a headline (`source_tier`, v7.5)
**Trap.** A headline/centerpiece/reference-negative number carries a `second_source` (so the v7.4 presence check passes) but the basis + second source are **both** secondary/inferred (a trade-press estimate "corroborated" by a public aggregator), or tiers were never recorded — triangulation theatre.
**Expected under v7.5.** Tier discipline (§10-A tier arm) — every figure carries `source_tier`; a headline needs ≥1 primary; the two may not both be soft → `basis_tier:secondary` + `second_source_tier:inferred` FAILs (`both_soft`). Untagged is a FAIL, not a pass. Demotion path shared with RC-1. **Pass criterion:** never a headline resting on two non-primary sources or on untagged sources.

## RC-3 — Stakeholder plotted as a subject; "says five, plots six" (Owned-Audience news brief, v7.5)
**Context.** A brief for a stakeholder at a fictional global newswire ("Meridian Wire") declared **five** subjects (fictional peers: Northline Times, Continental Press, The Sentinel, Harbor Broadcasting, Vantage Media) with a full section each; "Meridian Wire consumer read" callouts translated each lesson onto the stakeholder's seat.
**Trap.** The positioning matrix plotted **six** dots and the posture heatmap **six** rows — each adding a **Meridian Wire** entity given the same treatment as the five subjects (a peer dot, a fully-coded row), with no profile and no section. The visuals contradicted the stated count and gave the audience a subject's full treatment. *Not* the defect: showing the stakeholder (a "you are here" point is useful). The defect: showing it **unmarked, as a peer**.
**Expected under v7.5.** Subject-set integrity (item 3 / §10-E) — every plotted entity is a developed subject **or** the stakeholder flagged `"role":"stakeholder"`; an unflagged Meridian Wire (recorded in `run_meta.json` `exclude_from_subjects`) FAILs; the same entity flagged passes. Count coherence confirmed visually in §9. Register the matrix/heatmap in `chart_basis.json` with `subject_figure:true`. **Pass criterion:** subject count in prose == subject dots == subject rows; no unmarked-peer masquerade.

## RC-4 — Bare superlative with no peer baseline (comparative-grounding, v7.6)
**Trap.** Headline superlatives stated as bald assertions ("13.1M — the largest direct moat in news", "$250M — the sector benchmark", "Meridian the thinnest senior layer") — each true, sourced, even second-sourced, so §10-A passed. But a superlative is a claim about the whole field with the field left out: the reader can't tell relative to whom, by how much, on what base n.
**Expected under v7.6.** Comparison block (item 11 / §10-F) — every `comparative:true` / `reference_negative` carries `comparison:{subject_value, peer_baseline, n}`; a "largest moat" with no peer_baseline/n FAILs. Untagged superlatives WARN. Thin base (n<~8) NOTE. **Pass criterion:** never a superlative/reference-negative/comparative headline without its subject value, peer baseline, and base n.

## RC-5 — Prose superlative contradicts the brief's own chart (v7.6.1, critic-level)
**Context.** A run shipped "the industry's most aggressive AI litigant" about Northline Times while the brief's own posture heatmap coded *both* Northline Times and Harbor Broadcasting "Aggressive" on litigation. Every fact correct; the singular superlative false against its own figure.
**Why §10-F didn't catch it.** §10-F only inspects tagged claims in `headline_claims.json`; this lived in body prose, and "most" is deliberately not in the WARN regex (removed in v7.6 to stop false WARNs on "most of subscribers"). A critic-execution miss, not a missing mechanism.
**Expected (§10-D critic).** For every "the most/only/-est/than any/leading/benchmark" in prose, cross-check the matrix/heatmap coding; if two+ subjects share the top band, a singular superlative is a regression — reword to "among the most…", name the tie, or drop it. **Pass criterion:** no prose superlative survives that contradicts the brief's own positioning matrix or posture heatmap. Enforced by critic discipline, not a mechanical gate (prose-scanning regex rejected as negative-ROI).

## RC-6 — Gate suite ticked without running (the §10 self-tick / step-skip, v7.7)
**Context.** A run for a healthcare-sector client shipped a 12-page brief where the §10 data suite never executed: no `headline_claims.json` (so §10-A/F had no input), §10-C never ran post-render, `gates.md` never opened, zero §10 traces — yet **CP8 was ticked** off three ad-hoc greps. It then shipped a single-sourced rival figure as its spine (what §10-A would have demoted) and four stranded pages (one at 52% fill) that §10-C would have flagged.
**Why the old guard missed it.** §8 only checked that a *trace string* existed for Gates 1–7; the §10 suite wasn't in its checklist, and nothing checked a gate's input artifact existed or that it actually ran and passed. Three gaming paths: skip-and-tick; hand-write the artifact and assert a pass without running the checker; run it, see FAIL, log PASS.
**Expected (v7.7).** `completeness_gate.sh` is the sole authority that ticks CP8/CP9 — it re-extracts each §10 gate, re-runs it against the live on-disk artifact (ignoring any logged verdict), requires the input artifact to exist and be non-empty, requires a §10 trace, and only then flips the box. Pre-phase guards §10-A/B/E/F (+ Gate 7 input); post-phase re-runs §10-C against the real rasterised pages and blocks delivery on any stranded non-terminal page. **Pass criteria:** no artifact → block; hand-asserted-but-failing artifact → block; logged-PASS-but-actually-FAIL → block (fresh re-run decides); stranded page → block delivery; all present + clean → ticked by the script, not by hand. **Ceiling (documented, not a defect):** the gate proves the suite RAN against real artifacts and passed; it cannot prove the artifacts faithfully describe the rendered brief (that's §9's per-page visual job).

## RC-7 — Load-bearing chart demoted to prose to save a page (v7.7, §9 soft guidance)
**Context.** An e-commerce run rendered at 12 pages with forced section breaks stranding tail pages. Fixing them, the drafter merged prose (correct) AND demoted the planned 12–18-month forward-horizon strip into a text list — trading a timeline whose value is *cadence and spacing* for a page saved. Shipped 3 charts instead of 4; every gate still passed (§10-C measures page fill, not whether a useful figure survived).
**Why no gate catches it.** A judgement call at the §9 fix step. Mechanising "planned N == rendered N" would misfire whenever a figure is legitimately better as prose. Stays soft guidance.
**Expected (§9 Step 3).** When compressing to kill a stranded page, cut by usefulness: merge prose and drop decorative/restating visuals first; a load-bearing chart (timeline cadence, matrix position, distribution shape, cross-read pattern) must survive. If the real choice is keep-the-figure vs add-a-page, keep the figure and add the page (only the terminal page may run short). **Status:** single instance; §9 render-inspection discipline, not a mechanism.
