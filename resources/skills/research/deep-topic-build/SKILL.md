# Deep Topic Build

**Contract**
- **Input:** the user's 1–4 topics and the instruction to keep the result in the vault ("do very deep research on X, Y, Z and store and link them to the vault"). More than 4 topics means splitting into separate runs.
- **Output:**
  - `cbrain/projects/<Topic>.md`, one topic anchor per topic (`type: topic`). If the anchor already exists, append a dated `## What changed — <date>` section instead.
  - `output/research/<YYYYMMDD>-<slug>.md`, one cross-topic report (`template: report`), plus its same-stem `.html`.
  - One reasoned backlink line in ≤5 existing notes per topic, plus one line under `## Log` in `cbrain/daily reports/<YYYYMMDD>.md`.
  - The report's index note, generated by `vault-hygiene/deliverable-index` under that skill's own `vault_writes`.
  - STATE_ROOT `output/.runs/<YYYYMMDD>-<slug>/`, containing:
    - `RESPONSE.md`, the control spine
    - `EVIDENCE.md`, holding the verification table, the conflict log and the exclusions
    - `children/<topic>-<tech|industry>/TASK.md` and `RESPONSE.md`
- **Allowed tools/artifacts:**
  - Agent (general-purpose, fresh, background) and SendMessage for resuming children.
  - WebSearch and WebFetch, for the parent verification pass only.
  - Read and Grep over the repo and vault.
  - Write and Edit only on the output paths above.
  - `scripts/vault_links.py`, `reading-pages/scripts/page.py`, `deliverable-index/scripts/index_deliverables.py`.
- **Budget:**
  - Children: 2 per topic, ≤30 web calls each.
  - Parent verification: ≤5 web calls per topic, ≤15 per run.
  - On any cap, deliver what you have and name the gap in the note, the report and the final message. Never raise a child's cap mid-run.
- **Done when:**
  - `page.py check` prints `OK` for the report.
  - `vault_links.py check` prints `OK` for every new topic note and the report.
  - A re-run of `index_deliverables.py` reports `0 new/changed`.
  - `grep -cF '[ ]'` on the spine returns 0, with every box `[x]`.

**Triggers/Context**
- **Use when:** the user names topics and wants them researched *in depth* and kept in the vault, in an interactive session.
- **Use something else when:**
  - the question is delegated from the console → `deep-research`
  - it is "bring me to X" → `topic-build`
  - there is a single shared source → `source-distillation-topic-note`
  - it is one quick fact → answer directly.

**Core Blueprint**
1. **Harvest.**
   - `grep -ril` every topic and its synonyms and abbreviations across `cbrain/` (projects, Clients, notes, Deliverables).
   - Record which anchors and people each topic touches; these are the link targets for step 12.
   - Treat agent-written vault content as unverified. It may shape the packets' "cover at minimum" lists, but it never gets fed to children as fact.
2. **Scope and state the plan in chat.** Before launching, put these in one message:
   - the skills applied
   - each ambiguous term's working interpretation
   - the budget
   - the vault outputs

   If a term is vendor-coined, include its two readings and add "is this a real category?" to the questions. This chat plan replaces `deep-research`'s console check-in, and the user can redirect while the children run. Ask a question first only when an ambiguity changes which sources to read *and* can't be covered by including both readings.
3. **STATE_ROOT.**
   - Write `RESPONSE.md` with a header line naming `skills: research/deep-topic-build` (the weekly `verdict_sweep.py` matches runs by it), then the question, the assumptions, and these boxes:
     - Scope
     - Gather (children reopened from disk)
     - Verify
     - Report (`page.py` OK and rendered)
     - Topic notes
     - Backlinks and daily line
     - Deliverable index
     - Feedback block
   - Write `EVIDENCE.md` with its header.
4. **Packets.** Write two children per topic from [`references/child-packet.md`](references/child-packet.md), copying the Rules and Output blocks verbatim:
   - `<topic>-tech`: definitions, lineage, taxonomy, frontier systems, benchmarks, skeptic view.
   - `<topic>-industry`: deployments with a maturity level, economics, funding and M&A, vendors, Europe and sovereignty, regulation, build/buy/ignore.

   Each packet's "cover at minimum" list names the systems, companies and benchmarks you expect, so children verify them instead of recalling them.
5. **Launch** every child in **one** message: background, fresh context, the launch prompt from the reference.
6. **While children run:**
   - Prepare only work that does not depend on their results: read the target notes' `## Links` / `## Related` sections, check the house style (`cbrain/projects/AI Fluency.md`), run `page.py spec`.
   - If the Stop gate fires while you wait, turn every open box into `[~]` and add `Paused awaiting sub-researchers (<ids>) (<date -Iseconds>)`. Turn them back to `[ ]` on resume.
   - Never write the literal `[ ]` inside spine prose; the gate greps for it.
7. **Failures (rate limit, API error, cut-off).**
   - For each child, check whether its `RESPONSE.md` exists and has all 8 sections.
   - **Resume** incomplete children with `SendMessage` to the same agent id ("continue; your call count carries over; write RESPONSE.md"). This keeps their gathered context and their budget count.
   - Never launch a fresh replacement for a child that already gathered material.
   - Log the interruption in the spine.
8. **Integrate.**
   - Reopen every `RESPONSE.md` from disk.
   - Write each topic's note as soon as both of its children are in; don't wait for the slowest topic.
   - Build the **conflict list**: the same fact with different values; one child excluding as "anomalous" what another asserts; numbers that differ by a factor (half-model parameter counts, a commitment reported as a price).
9. **Verify (parent, verifier-separation).**
   - **Pick the release-critical claims:** every deal or funding figure you will headline, every number in a TL;DR or `metrics` block, every launch date, every claim that settles a conflict.
   - **Check each against a primary or reputable source.**
   - **Record the results in `EVIDENCE.md`:** a table of claim · verdict (`CONFIRMED`, `CONFIRMED with correction`, `NOT CONFIRMED`) · source checked. Add the conflict log, with a resolution per item.
   - **List exclusions:** low-confidence items that will not be repeated anywhere.
   - **Propagate:** corrections go into every note and the report; mark verified figures *parent-verified* in TL;DRs.
10. **Topic notes.** Write each note in this house style:
    - **Frontmatter:** `tags`, `type: topic`, `status: active`, `created`, plus `aliases` for abbreviations.
    - **Anchor paragraph:** `[[links]]` to existing notes only, and the sibling anchors.
    - **Callouts:** a Source callout (run and report paths) and an Evidence-status warning naming what is vendor-reported.
    - **`## TL;DR`:** point first; each number with its source and date.
    - **Taxonomy and who-leads tables.**
    - **`## Evidence vs. hype`.**
    - **`## Industrial / manufacturing relevance`:** a table with maturity (`shipped / production / pilot / demo / speculative / prohibited`) and a call per use case.
    - **`## Business relevance (Business → Product → Technology)`.**
    - **`## Applied — <project>`:** only when a vault project genuinely fits, and marked as inference.
    - **`## Content & talk angles`:** story-led and buyer-framed, per the LinkedIn content rule.
    - **`## Open questions & gaps`.**
    - **`## Links`.**
11. **Report.** One cross-topic `template: report` page with these sections:
    - `## Bottom line` (buy / pilot / ignore)
    - a `metrics` block with verified numbers only, each with its source
    - how it was researched
    - one part per topic
    - the cross-cutting pattern
    - what it means for the user (vault links)
    - `## Confidence and gaps`, including the exclusions and the budget
    - `## Sources`, primary sources first

    Run `page.py check` until `OK`, then `page.py render`.
12. **Link.**
    - `python3 resources/skills/research/deep-topic-build/scripts/vault_links.py check <new notes> <report>` must print `OK`.
    - Write a spec with ≤5 existing notes per topic. Each line reads `- <Sibling|Related|Topic|Person>: [[New]] — added <date>; <one-line reason carrying the concrete fact>`.
    - Add one daily line under `## Log`, then run `vault_links.py append spec.json`. It inserts at the end of the first block under the heading, is idempotent, and creates a missing heading.
    - **Person notes:** only with a concrete conversation-hook fact. Flag hooks that come from a secondary source.
    - **Never append into generated notes:** deliverable index notes, or ledgers that a watch skill maintains (e.g. `Andrew Ng - Letters Ledger`).
13. **Index.**
    - Run `python3 resources/skills/vault-hygiene/deliverable-index/scripts/index_deliverables.py`, then re-run it until it reports `0 new/changed`.
    - Add `- Deliverable: [[<index note>]] — …` to each topic note's `## Links`. The generated note may not auto-link every anchor; never hand-edit it.
14. **Close.**
    - Tick the spine.
    - In the final chat message, cover:
      - what landed (paths)
      - one headline per topic
      - the corrections the verification made
      - the exclusions
      - the budget and any interruption
    - End with the Feedback & Skill Verification block (Charter §7).

**Optimizations/Gotchas**
- **Fresh children, no vault.** The vault holds agent-written claims nobody has checked. A child that reads them launders them into "research".
- **Children disagree in predictable ways**, and step 9 exists for these (all seen on 2026-10-23):
  - one child drops a true fact as an "anomalous snippet" while its sibling asserts it (AMD × World Labs);
  - parameter counts reported for half of a two-part model (Cosmos 3: 8B/32B vs 16B/64B);
  - an investment commitment reported as a purchase price (SAP × Prior Labs).
- **Pair every saturated vendor benchmark with an independent task-level test** in the TL;DR. On 2026-10-23 that pairing (Big Bench Audio at 97–100% vs τ-Voice at 26–51%; Cosmos "#1 open" vs Physics-IQ at 29.5%) was the most decision-relevant finding across all three topics.
- **Vendor-coined terms** (e.g. "Large Quantitative Model") get a verdict, the underlying families, and a buyer's checklist. Never just the vendor's definition.
- **Children hitting the 30-call cap is normal.** List the gaps; don't raise the cap. Breadth comes from the second child per topic, not from a bigger budget.
- **A rate-limit kill stops every background child at once.** Resuming each by agent id lost nothing; relaunching would have re-spent ~120 web calls.
- **Generated-note blind spot.** `deliverable-index` auto-links only some anchors. Link from the topic notes to the index note, not the other way round.
- **No headless variant on purpose.** There is no `.claude/agents/` job for this skill, so there are no hook-enforced `write_scopes`. It runs interactively, under `vault_writes` by policy (Charter §6).
