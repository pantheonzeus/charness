# HARNESSCARD — charness

Disclosure card for this workspace's harness, following the Control–Agency–Runtime (CAR) template proposed in He et al., "Harness Engineering for Language Agents" (preprints202603.1756.v1). The paper's audit of 40 harness-relevant works found the base model is only 1 of 8 required disclosure fields — the other 7 are what this card exists to make explicit and inspectable. Fill status: 8/8 fields have an in-repo answer; the Evaluation protocol is small and covers harness behaviour, with deliverable quality started for one job — see that row.

| Field | Disclosure |
|---|---|
| **Base model(s)** | Claude Code CLI. Interactive sessions: model chosen per session (`/model`). Headless jobs: the pinned `model:` and `effort:` in each `.claude/agents/<job>.md` (15 of 19 on Sonnet, 4 on Opus), plus the model family's addendum from `resources/models/`, appended by `run_agent.sh`. **Portability is measured, not assumed:** model-swap test on the regression suite, 2026-10-24: Sonnet 5/5 probes pass^3, Haiku 4/5 (routing, injection resistance and headless-shell discipline held; on the capability-check probe Haiku answered correctly 3/3 but once invented an invocation path that doesn't exist). A job's model changes only when the candidate holds pass^3 on that job's probes (`regression.py --model`); harness gains are model-specific (arXiv:2609.01437, 2610.27435), so the suite reruns on every model upgrade. |
| **Control artifacts** | `CLAUDE.md` (auto-loaded), [`Charter.md`](Charter.md) (run-level policy), [`Soul.md`](Soul.md) (voice mechanics/inviolable lines), `IDENTITY.md`/`IDENTITY.example.md` (the persona itself — private/gitignored vs. public default), `resources/skills/INDEX.md` (skill registry) → per-skill `SKILL.md` (the executable NLAHs), `resources/skills/MODULES.md` (module vocabulary), `resources/skills/_shared/*.md` (shared procedures: evidence gate, delegation-handoff, verifier-separation, self-evolution, change-manifest). |
| **Runtime policy** | `.claude/settings.json` hooks: `SessionStart` injects `INDEX.md` + the memory index + the active persona (`IDENTITY.md` or its public fallback) + the active employer pack (`scripts/employer.py context`: role, provider bindings, the `employer-internal` confidentiality class) every session; `UserPromptSubmit` (`scripts/skill_router.py`) preselects the likely skills per prompt (the full INDEX is past the 10,000-character hook cap, so SessionStart carries a compact registry); `PreToolUse` (`write-boundary.sh`, symlinks resolved) gates Write/Edit/MultiEdit/NotebookEdit — repo zones for every session, and for a headless job (`CBRAIN_JOB`, exported by `scripts/run_agent.sh`) only the `write_scopes:` declared in its `.claude/agents/<job>.md`; `PostToolUse` (`scripts/ingest_lint.py hook`) stamps `provenance: derived-untrusted` on a vault note written by a session or job that took in outside text (decided from the transcript, not by the writer), and the same script's `PreToolUse` asks before a memory write in such a session; `Stop` (`control-spine-gate.sh`) checks the control spine before a run ends. Charter §4: substantive multi-step runs keep durable state under `output/.runs/<slug>/` (`RESPONSE.md` control spine + `EVIDENCE.md`), reopened by path across steps and after context compaction — no reliance on in-context summarization surviving compaction. |
| **Action substrate** | Claude Code's tool surface (Bash, Read/Write/Edit, Agent, Workflow, WebSearch/WebFetch, NotebookEdit) plus repo-specific CLIs a skill's `requires:` block declares (e.g. `nlm`/`notebooklm-py` for NotebookLM, Obsidian as the vault filesystem). MCP connectors (Figma, Slack, workspace-mcp) require interactive auth, absent in headless/cron runs. |
| **Execution topology** | Single main agent by default. Charter §5: child agents only when delegation genuinely improves coverage/latency/specialist focus, via file-backed task packets (`TASK.md` → `RESPONSE.md`), never inline-reply handoff. Multi-agent `Workflow` fan-out is gated behind explicit user opt-in ("ultracode" or a direct ask) — never spun up unprompted. |
| **Feedback stack** | [`evidence-gate.md`](resources/skills/_shared/evidence-gate.md) (release-critical claims tagged observed/inferred/assumed, gated before shipping), [`verifier-separation.md`](resources/skills/_shared/verifier-separation.md) (distinct checking step, e.g. `link_audit.sh`), [`self-evolution.md`](resources/skills/_shared/self-evolution.md) (within-run reflect→redesign→retry, capped at 5), Charter §7's end-of-task feedback prompt, and [`change-manifest.md`](resources/skills/_shared/change-manifest.md) for between-session harness edits. |
| **Governance / observability** | `write-boundary.sh` as the permission gate on file mutation, holding each headless job to its declared write scopes; `egress-guard.sh` on WebFetch/WebSearch (no email address, encoded blob or oversized query leaves; 0 false positives replaying 2,878 past calls); `send_gate.py` on every MCP send tool (fails closed: the person's explicit yes after a read-back naming every recipient, plus `scripts/outbound_gate.py`'s scan for other clients, third-party contacts and internal channels); the Bash sandbox for the ingest-heavy headless jobs (`sandbox: true` in their agent files: writes only in the repo, network only to pypi); `code_mode: true` for a job that runs code it wrote: sandbox forced, and Bash writes to the vault and the harness denied at OS level (canary 2026-10-27); `scripts/vault_api.py`, the typed batch writer through which Bash-run vault writes keep the job's write scopes and provenance labels; a circuit breaker in `run_agent.sh` that stops all jobs after three API-pressure failures; ingest provenance (`provenance: untrusted-ingest`, weekly `scripts/ingest_lint.py` sweep); Charter §6 makes vault writes a declared side effect (`vault_writes:` in SKILL.md frontmatter); git as the audit/replay log for every skill and Charter edit (nothing is a silent in-place rewrite), and a private local git history of the vault (`scripts/vault_history.sh`, never pushed) with one commit per headless run, so any run's vault changes can be reviewed and reverted; the memory dir (`MEMORY.md` + one file per fact) as durable cross-session state, separate from the vault's own graph-link audit (`link_audit.sh` — no islands). Run telemetry: the per-job ledger now carries API time, time to first token, tokens, subagents and files written (yield) per run; OpenTelemetry export is opt-in via `CBRAIN_OTEL_ENDPOINT`. |
| **Evaluation protocol** | **Covered, small, growing.** A harness regression suite (`resources/skills/workflow-ops/run-forensics/evals/regression.json`, runner `scripts/regression.py`): one probe per recorded failure code or Charter rule (SKILL_MISROUTE ×2, capability check before denial, untrusted-ingest injection, PERM_BLOCKED in headless Bash), each a headless run against the real harness with read-only tools, graded by code from the transcript and reported as **pass^3**. Baseline 2026-10-24 on Sonnet: 5/5 probes pass^3 after two logged grader corrections (3/5 under the frozen graders; every frozen-grader failure was read and was a grader proxy, not a harness failure). Run before and after every harness edit and on every model change (`--model`). Alongside: the skill preselector's recall@5 on the routing golden set (held-out 24/31, quiet on 12/15 no-skill prompts, 2026-11-08), deterministic tests for every hook (write-boundary 30, egress 15, send gate 17), the change-manifest predict→verify ledger with matched-baseline and judge-probe fields, and run-forensics' recurrence tracking on production runs. Output quality (since 2026-11-08): `judge.py` grades daily-intel briefing items against rules quoted from the job's skill, critique first, with the source text the run fetched; it flags nothing (code QUALITY_JUDGE) until it agrees with the principal's own labels at TPR and TNR ≥ 0.8 on ≥ 10 pass and 10 fail labels. Not yet calibrated. Every job's repeated research is reported per model. Still missing: output-quality evals for the other deliverables (plans, posts, preps). |
